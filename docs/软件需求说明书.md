## 1. 范围与验收
选题三：模拟智能宿舍自动化，不接入真实硬件。主流程：启动恢复→编辑规则→调整环境→执行联动→查看顺序与冲突→修改优先级→保存→终止进程→重启核对。
F01：4 类设备：灯、空调、窗帘、插座；分别支持开/关动作与手动控制。
F02：温度 0～50℃、照度 0～1000lx、人数 0～8；拒绝非有限值、非整数人数和越界输入。
F03：默认 4 条规则；可新增、修改、删除、启停；每条 1～2 个 AND 条件，可修改阈值、设备、动作、优先级和名称。
F04：只在用户点击“执行联动”时执行一次；每次按优先级降序、同优先级按 id 升序执行，争夺同设备时第一条匹配规则获胜，其余明确记为冲突跳过。重新执行可再次匹配，无冷却/边沿触发。
F05：每条规则记录输入、判断结果、原因、原值/目标值与执行次序；未匹配也留痕。最多保留最近 200 条记录。
F06：学习、夜间两组可选场景只调整环境；需要点击执行才产生联动。
F07：Preferences 保存完整快照：版本、环境、设备、规则、日志和下一个规则 id。每次业务修改后保存；写入失败明确显示且支持重试，不宣称已保存。
F08：损坏/未知版本快照不覆盖，显示错误并阻止写入；用户显式确认重置后恢复默认。
F09：单用户、本地离线；卡片展示状态，颜色和文字同时反馈。保存期间禁止修改，避免并发写入覆盖。

## 2. 模块及接口
Index：ArkUI 视图、规则表单、环境编辑、场景按钮、设备状态、日志展示；调用引擎并提交快照。
Engine：无 UI/平台依赖的确定性纯业务函数；validateEnvironment、validateRule、createDefaultState、run、encode、decode。
Store：load(context): Promise<AppState>；save(context,state): Promise<void>；Preferences 单键 JSON + flush。
UIAbility：创建 Stage 并加载 pages/Index。
接口约定：run(state, now) 返回新状态，不修改原状态；非法输入抛 Error；日志时间由调用方传入；只有 UI 访问 Store；Engine 不访问系统时钟、UI 或存储。

## 3. 数据模型
Environment {temperature:number, light:number, people:number}。
Device {id:string, name:string, on:boolean}；固定 light/ac/curtain/socket 四项，窗帘 on 表示打开。
Condition {field:string, op:string, value:number}；字段为 temperature/light/people，op 为 lt/gt/eq。
Rule {id:number,name:string,enabled:boolean,priority:number,conditions:Condition[],deviceId:string,action:boolean}。
ExecutionLog {sequence:number,time:string,ruleId:number,ruleName:string,input:Environment,status:string,detail:string}。
AppState {version:number,environment:Environment,devices:Device[],rules:Rule[],logs:ExecutionLog[],nextRuleId:number}。
priority 为 0～100 整数；规则名 1～30 字；最多 30 条规则；日志最多 200 条；id 唯一正整数。

陈俊宇独立承担需求、整体设计、引擎、界面、持久化、测试和集成，无组队、无跨人接口约定，个人承担整体设计与集成结果。源码由本人账号 2026chen-cmyk 提交，提交历史见仓库 Commit 列表。
表单错误不修改状态；保存失败保留内存状态供重试并提示风险；首次无存档使用默认值；读取错误需重置确认。
应用不需要网络权限，Mock 环境不代表真实传感器。账号、签名、SDK 与证书由开发者本机配置，仓库不包含密钥。
